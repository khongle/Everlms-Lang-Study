Why does my useState value not update immediately inside the click handler?

Linh Tran Student
Jul 11, 2026 · 9:14 AM

I am working through Section 2: React Fundamentals and hit something confusing. In the code below, I call setCount and then immediately log count on the next line, but it still shows the old value:

function handleClick() {
  setCount(count + 1);
  console.log(count); // still the old value?
}

Is this a bug in my code, or is this just how React works? Would appreciate a pointer to the right mental model.

This is expected. State updates in React are asynchronous and batched inside event handlers — count keeps its value from the current render until the component re-renders. Reading it right after calling the setter will always show the old value in that same function call.

Michael O.
9:47 AM

To add to Sarah's answer: if you need the updated value right away, use a useEffect that depends on count and log it there instead. That runs after the re-render, so it will show the new value.

That makes sense, thank you both. So the takeaway is: never trust the state variable's value inside the same handler that just updated it.

Sarah Chen Instructor

Exactly. And if the next value depends on the previous one, prefer the updater form — setCount(c => c + 1) — so you are never reading a stale closure value at all. It is covered in the "Handling events" lesson if you want a refresher.
