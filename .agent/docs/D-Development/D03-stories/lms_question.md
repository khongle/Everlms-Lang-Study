## Scope

Provides the question bank for the EverLMS assessment system:

- `lms_question`: translatable content entity with 8 bundles defined via `lms_question_type` config entity. All bundle-specific fields coexist on the base entity (no per-bundle storage split). Supports `inline_entity_form` for embedding in quiz builder.
- `lms_answer`: child entity for single_choice / multiple_choice answer options.
- `lms_matching_pair`: child entity for matching-type left/right pairs.
- `lms_question_type`: config entity that defines the 8 bundles installed via `config/install/`.
- `QuestionAccessControlHandler`: shared across all three entities; delegates to `lms_base` course permissions.
- `QuestionForm`: minimal wrapper over `ContentEntityForm`; no bundle-conditional field hiding.
- All admin CRUD routes auto-generated by `AdminHtmlRouteProvider` (no custom `lms_question.routing.yml`).

Full design: [`../C-Design/C05-modules/lms_question.md`](../../C-Design/C05-modules/lms_question.md)

## Notes

### Technical Debt

| ID | Severity | Description |
|----|----------|-------------|
| DEBT-QUEST-01 | Low | `QuestionForm` renders all 14 base fields for every bundle; bundle-irrelevant fields clutter the instructor UI (e.g., `field_correct_answer` shows on essay questions) |
| DEBT-QUEST-02 | Low | No question versioning; editing a question after quiz attempts exist can invalidate historical grading context |
| DEBT-QUEST-03 | Low | `lms_answer` and `lms_matching_pair` have no standalone admin UI; only accessible via inline entity form or direct URL hack |

### Architecture Note

`lms_question` contains **no grading logic**. The grading strategy system (`GradingStrategyFactory`, 8 strategy classes, `QuestionGradingInterface`) lives entirely in `lms_quiz`. The separation is intentional: question bank is a pure data module; grading is quiz-engine logic.

See `../C-Design/C05-modules/lms_question.md` for the bundle-to-field mapping table and full entity field definitions.
